# InsightFlow AI V2.8.2 demo guide

This guide uses the additive dashboard workflow. The original V1 `POST /analysis/query` and the V2.6 `POST /analysis/visualize` artifact boundary remain available and unchanged. The new `POST /analysis/workflow` composes the existing planner, multi-agent executor, verifier, bounded correction service, and visualization service. Visualization remains a consumer of artifacts and is called only after final verification passes.

## Start the backend

Open PowerShell in `C:\dev\insightflow-gemini-step7-v2.8.2\backend`. This selected checkout currently has no `backend/.venv`; provision Python 3.12 and install the existing backend requirements before starting the server. The Python 3.12 interpreter available during validation was `C:\ProgramData\anaconda3\python.exe`. Do not copy a virtual environment from another checkout. Use the existing `backend/.env` configuration; do not put credentials in commands or source files.

```powershell
Set-Location C:\dev\insightflow-gemini-step7-v2.8.2\backend
& 'C:\ProgramData\anaconda3\python.exe' -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

The validation work used the existing Python 3.12.7 environment from `C:\dev\insightflow-ai\backend\.venv` without changing its dependencies. The commands above create a local environment in this checkout when you are ready to run the demo; dependency installation is a one-time setup step.

`backend/.env` is loaded by the existing Pydantic Settings configuration. For a Gemini request, the process needs an authorized `GEMINI_API_KEY`. Never print the file or key.

If Python reports that `SSL_CERT_FILE` points to a missing or invalid CA bundle, the backend returns a sanitized configuration error before contacting Gemini. Remove a stale override for the current PowerShell process with:

```powershell
Remove-Item Env:SSL_CERT_FILE -ErrorAction SilentlyContinue
python -c "import ssl; ssl.create_default_context(); print('TLS trust configuration loaded')"
```

If this machine requires an approved custom CA bundle, set `SSL_CERT_FILE` only in the PowerShell process that launches the backend, using the administrator-provided bundle path. Certificate verification must remain enabled. Do not commit a machine-specific CA path or change TLS verification settings.

## Start the frontend

Open a second PowerShell window. The frontend expects the API at `http://127.0.0.1:8000` by default.

```powershell
Set-Location C:\dev\insightflow-gemini-step7-v2.8.2\frontend
npm run dev -- --host 127.0.0.1
```

## Demonstrate the V2 workflow

1. Open the Vite URL printed by the frontend.
2. Upload the authorized sample sales CSV, then review its preview and profile. The uploaded `dataset_id` is passed to the V2 workflow; no fixed ID or pasted artifact payload is used.
3. In Section 5, try **What is the total revenue?** or **Show revenue by region.**
4. Inspect the plan, execution, verification, and (if invoked) correction trace. A chart is displayed only when the final verification status is `passed` and visualization traceability matches the active dataset.

Revenue derivation is enabled only for an exact dataset snapshot with a trusted semantic manifest and registered revenue definition. A different upload, even with similar headers, may return a structured unsupported/validation result. The application does not infer metric definitions from names or values.

Rows are not automatically deduplicated. Duplicate source records remain in sums and counts unless the plan explicitly requests the supported exact-duplicate operation. Missing grouping values are shown under `(missing)`; no missing category is invented or imputed. V2.6 may return a structured unsupported visualization when the verified result is scalar, empty, malformed, or otherwise lacks a safe chart shape.

The UI does not call the official evaluation runner, load benchmark ground truth, or create research results. A successful dashboard demonstration is software behavior evidence, not an official Step 7 experiment or research metric.
