# V2.8.2 Canonical LF Reproducibility Clarification

## Status and scope

This clarification fixes the byte representation used to identify the already frozen InsightFlow-Bench v1.0 artifacts for V2.8.2 execution. It does not create a new benchmark, amend benchmark meaning, or change the experimental protocol. The V2.8.2 runtime hash authority is `backend/data/evaluation/step7_v1.0/artifact_hashes_v2.8.2_v1.0.json`.

## Canonical byte representation

The authoritative representation is the exact canonical LF byte sequence checked out from the implementation Git revision. SHA-256 MUST be computed over those exact bytes. Files MUST contain LF (`0x0A`) line endings only; any carriage return (`0x0D`) byte makes an artifact non-canonical and MUST fail integrity verification. Hash verification MUST NOT silently normalize CRLF input.

The repository `.gitattributes` rule is `* text=auto eol=lf`. The canonical hash manifest identifies the four artifacts and their SHA-256 values. The runtime integrity verifier checks the exact artifact bytes against that manifest before loading the official benchmark.

## Preservation of frozen content and decisions

The questions, ground truth, dataset rows, columns, and values are logically unchanged. LF-to-CRLF conversion changes only line-ending bytes; it does not change parsed JSON records or CSV rows. The prior hashes represented CRLF working-tree bytes and are retained in historical V1.0/V2.8.1 freeze records and existing diagnostic artifacts as historical metadata. Those records and artifacts MUST NOT be rewritten by this clarification.

The V2.8.2 semantic behavior, benchmark applicability/exclusion rules, category/difficulty labels, evaluator/scoring semantics, baselines, ablations, research questions, error taxonomy, error-injection schedule, and statistical procedure remain unchanged. This is solely a reproducibility/hash-authority correction, not a benchmark-content change or a research result.
