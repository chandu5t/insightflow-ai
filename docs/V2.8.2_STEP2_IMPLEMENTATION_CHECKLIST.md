## C. Ordered date predicates

- [ ] Permit ordered predicates only on exact columns with trusted `date` role.
- [ ] Enforce strict `YYYY-MM-DD` calendar-date parsing for literals and non-missing source values.
- [ ] Implement `on or before D` as `lte D`; inclusive ranges as `gte D1` AND `lte D2`; calendar months as first-day-inclusive through next-month-exclusive.
- [ ] Reject malformed/impossible literals and reversed bounds during plan validation where knowable.
- [ ] Fail the operation on invalid non-missing source date values; do not return partial output or coerce/discard them.
- [ ] Ensure missing dates do not match ordered comparisons and remain selectable only through explicit missing predicates.
- [ ] Add no new filter operator and no timezone, timestamp, locale, trimming, or coercion behavior.
