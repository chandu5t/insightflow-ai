# V2.2 Analytical Planner

Status: implemented as an additive planner-only capability. This component does not execute plans and does not replace the V1 query workflow.

## Boundary

`POST /analysis/plan` accepts a question and optional caller-provided dataset context and metric definitions. It returns a structured plan, normalization/schema validation, structural plan validation, validation errors, and planner metadata. It does not load datasets, access PostgreSQL/pgvector, perform RAG, calculate values, execute Pandas, or invoke the V1 classifier.

V2.2 ends at `VALID` or `INVALID`. Supervisor/agent execution belongs to V2.3, independent verification to V2.4, and correction/replanning to V2.5. `/analysis/query` and V1 analysis behavior remain separate.

## Plan representation

`AnalysisPlan` contains a controlled intent, reasoning type (`simple`, `multi_step`, `definition`, or `unsupported`), steps, and optional `unsupported_reason`. Each `PlanStep` has a unique `step_id`, operation, human-readable description, inputs, parameters, and dependency IDs. Empty `inputs`, `parameters`, and `depends_on` serialize explicitly.

The metadata-only operation registry contains exactly: `select_columns`, `filter_rows`, `derive_metric`, `group_by`, `aggregate`, `sort`, `rank`, `top_n`, `bottom_n`, `count`, `distinct_count`, `calculate_difference`, `calculate_percentage_difference`, and `compare_groups`. It is not an executor.

Normalization canonicalizes only explicit known aliases. It does not add, remove, reorder, or repair steps, dependencies, columns, or analytical meaning. The plan validator reports unknown operations, missing/unallowed parameters, duplicate IDs, invalid dependencies/order, cycles, and invalid unsupported/definition representation. A generated plan that fails plan validation returns HTTP 200 with `valid: false`; malformed requests are 4xx and planner/provider failures are safe 5xx errors.

## LLM and observability

The model receives the question, optional caller context, allowed intents/reasoning types, and registry metadata. It returns JSON only and must not calculate or generate executable code. Provider failures and unusable output are retried once; a second failure returns an explicit safe planner error. A generated but structurally invalid plan is not retried. There is no V1-classifier fallback or correction loop.

Structured JSON application logs record a generated request ID, question, model/version, plan, validation result/errors, retry flag, failure category, and latency. Token usage is recorded as unavailable because the existing Gemini client returns text only. Logs omit credentials, provider response text, and dataset context.

## Evaluation fixture and metrics

`backend/data/evaluation/v2.2_planner_fixture.json` is a small V2.2 development fixture, not InsightFlow-Bench and not a source of final research results. Labels are authored as expected planner structures and are independent of runtime planner outputs; keep them stable during a defined evaluation run.

`app.planner.evaluation.evaluate_planner_fixture` computes intent accuracy, plan validity rate, operation-selection precision (`|expected operation types ∩ selected operation types| / |selected operation types|`), step-coverage recall, dependency-edge F1, unsupported-operation rate, and mean planner latency from supplied fixture cases and responses. The V2.1 specification and V2.2 contract require tool/operation-selection accuracy but do not define its formula. This helper reports precision under its own explicit name; it does not claim that precision is the frozen accuracy metric or that the frozen accuracy metric has been calculated. The function does not call an LLM. No benchmark or performance result is claimed by this document.

## Limitations

- The registry is descriptive metadata only; no operation is executed in V2.2.
- Dataset context is supplied by the caller and is not checked against stored files or a live dataset.
- Metric definitions are accepted only as caller-supplied context; this module does not retrieve them.
- The existing Gemini client does not expose token usage, so token counts and cost are unavailable here.
- The development fixture is small and must not be treated as the frozen research benchmark.
